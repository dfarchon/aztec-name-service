# V8 targeted readiness operations

Public signing, proving, transactions, bridging and deployment are unconditionally disabled. `RealL1Adapter.execute` and `RealAztecAdapter.execute` throw before inspecting execution arguments. No environment variable, flag, budget value or capability token enables them. Their constructors accept only an RPC URL and contain no signer, wallet or credential-file input. Live read-only queries are permitted; a successful query does not authorize execution.

`FUTURE_REHEARSAL` freezes the independently recorded Sepolia/Aztec identity. Its Registry, Registrar, Resolver and budget remain null. They represent NEW future instances. Do not copy an old deployment's addresses into a deployment plan. The existing V8 plan retains its frozen classes, directed edges, 325 reservations in 11 batches and initialization checks. It is not connected to a public executor.

`LocalPinnedAdapters` uses Aztec SDK 6.0.0 and viem 2.57.1. It admits literal HTTP `127.0.0.1` endpoints only, verifies both chains are 31337 and Aztec is 6.0.0 with proofs disabled before creating an ephemeral wallet, and repeats the checks at the broadcast boundary. The L1 signer is a published deterministic test fixture; never fund its address on any public network. The SDK executes its actual simulation/prove pipeline with proving disabled. Transaction buffers are serialized/deserialized by the SDK and their SDK hashes compared; L1 hashes come from viem's signed transaction bytes. Proof bytes, witness data and serialized signed transactions are not written to evidence files.

The durability engine retains its historical `MockJournal` name for compatibility. Local adapters store actual SDK/viem hashes in it, synchronize the hash file and directory before broadcast, and use receipt-only recovery whenever a hash exists. A saved intent without a hash stops. A missing, pending, reverted or dropped receipt never triggers reconstruction or resend. Each local step allows at most 20 durable receipt observations across process restarts, including confirmed readbacks. A reservation is fsynced before each receipt RPC; its result does not consume another slot. RPC exceptions, reorgs and crashes after reservation retain that consumed slot. Legacy tracking entries conservatively consume one slot each; no old budget is reset. Integrity failures append an explicit halt and never resend. L1 receipt records include chain-derived block hash, number and timestamp. Confirmed SDK receipts contain block identity and execution status. Public read-only adapters verify the canonical Sepolia chain ID or the complete Aztec chain/version/proofs/rollup identity before each data read. Execution remains unconditionally paused. No public scheduler or bridge polling loop is implemented. The existing standalone delay/bridge helpers remain preview checks; caller-supplied timestamps do not establish an actual wait.

Each future direction requires application 86400 seconds plus protocol 86400 seconds, checked separately against canonical chain receipts and durable scheduling entries. Forward and rollback alone take at least 96 hours. The full cancellation chronology takes at least 192 hours plus confirmations. A public scheduler still needs canonical timestamp persistence, cancellation deadline reconciliation and reorg handling before it could use those helpers. No actual proposal or resume date exists.

Cost records distinguish exact local observations from estimates for public execution. L1 ETH pays transaction fees, L1 FeeJuice is the bridge asset, and L2 FeeJuice pays Aztec fees. Newly generated accounts would initially be uninitialized and unfunded. Gas and price margins do not fill missing components. A full amount or total stays null while a component is unknown. DA price must stay zero; any nonzero value or change stops the flow. Future execution would require fresh identity, prices, funds and readbacks within 60 seconds of each step and after waits, plus an owner-approved absolute budget. The current budget is null and public execution remains disabled regardless of these checks.

Remaining integration work includes an independently reviewed isolated public signer, authenticated receipt-derived scheduling, complete direct-payer chronology measurements, exact canonical bridge provenance/estimates, and new-instance initialization/readback orchestration. The local adapter is not a complete public rehearsal executor and does not establish real-proof latency or readiness.
