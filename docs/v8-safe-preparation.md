# V8 safe preparation operator

Run `node --import tsx e2e/src/v8-safe-operator-cli.ts` from the repository. It defaults to a plan preview. `--dry-run` is the only accepted argument. Execution, force, configuration and key-path arguments fail before any file or credential access. Environment settings cannot activate execution. This entry point does not create accounts, import wallets, access money files, connect to RPC, sign or send.

Public execution is unconditionally paused. A future implementation requires a new owner credential-risk disposition and budget approval, plus an independently reviewed signer boundary. This CLI and the mock durability engine are not live-ready.

The existing deployment plan retains the exact two V8 classes, forward/reverse edges, nonzero bound Registry owner, atomic constructor initialization and 325-reservation hash in 11 batches. Before any future bootstrap, deployment and resume readbacks must establish the instance deployer and initialized administrator equal that bound owner. The core, artifacts, layouts, legacy manifests and site are unchanged.

`v8-safe-operator.ts` provides a narrowly scoped mock checkpoint engine for local tests. It accepts only a `pure-local-mock` adapter at HTTP loopback on chain 31337. Its SHA256 payload hash is a toy identifier, not an Aztec signed/proved transaction hash. No real signing machinery is implemented. `MockJournal` requires an existing owner-only mode0700 directory, rejects symlink path components, uses an exclusive no-follow lock, stores the immutable complete run binding and mode0600 immutable journal entries, and synchronizes each file and directory. A lock left by a crash stops recovery until separately assessed; it is never automatically stolen. This protects against accidental drift and concurrent operators, not a malicious host owner rewriting all files.

The mock FSM writes intent before proof and the exact mock payload hash before broadcast. A failed proof stops. A hash or broadcast-boundary fsync failure prevents broadcast; restart sees intent or the saved hash. Every saved hash resumes TRACK ONLY, including an ambiguous send or a crash before send. Pending, unknown, reverted, dropped and reorg outcomes retain the hash and stop advancement. At most 20 receipt reads are permitted per step. No resend is available. Success requires readback before confirmation and readback again on confirmed resume. Already completed steps cannot repeat. The immutable binding includes network/proof identity, exact classes/code, artifact hashes, configuration, actors, reservations and directed edges. Any drift fails closed; no unknown-class/code fallback exists.

The injected read-only RPC wrapper uses an explicit method whitelist. It refuses account, signing, sending, wallet, debug-write, batch and unknown methods before invoking transport. There is no CLI transport or signer adapter. Future HTTP clients must avoid wallet middleware and independently bind endpoint identity; the whitelist alone does not establish server honesty.

`checkStepBudget` requires complete costs, nonnegative units, actor funds, an absolute ceiling and a sample at most 60 seconds old before each step. It stops on an overrun, a price above its approved ceiling, nonzero DA price or an activation margin of 900 seconds or less. Zero DA multiplied by any margin remains zero; a nonzero DA price requires a new approved absolute ceiling. This check never authorizes public execution. L1 wei and L2 FeeJuice must remain separate. The old 90 FJ / 0.006 ETH envelope is neither enlarged nor cleared.

Each application wait and each protocol wait is exactly 86400 chain seconds, independently checked. `readyAt = startedAt + 86400`; UTC+8 display is derived from that chain timestamp and is informational. The forward and rollback alone require at least 345600 seconds. Scheduled-cancellation demonstrations add waits: wait to the cancelled activation deadline, then start a fresh full application/protocol sequence. There is no public proposal now and no actual earliest resume date. Bridge recovery pins the expected message and proven readiness, permits at most 20 observations, and exits while waiting without repeating a deposit. The caller must persist the observation count and verify the proven canonical snapshot. These helpers do not implement public scheduling or autonomous polling.

Safe preparation can finish with an incomplete budget and unresolved source provenance. It cannot establish real-proof timing, actual public paid fees, funding sufficiency, credential safety or public readiness. The job report records those residuals separately from historical local verification.
