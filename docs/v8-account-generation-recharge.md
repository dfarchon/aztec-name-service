# Account generation and recharge boundary

Actual fresh public accounts do not exist. Actual key generation is blocked: this host and bot box share their UID with agents, and an isolated signer boundary has not been established. File modes and a quiet TXE process do not provide that boundary. Do not inspect or use old credentials, generate random persistent credentials here, or rotate, migrate, rename or delete existing money files.

A dedicated signer UID with no agent access, or an offline host with a reviewed Aztec signing arrangement, is a recommendation. Neither exists as an approved boundary in this job. The minimum owner action is to approve and establish a demonstrable isolated signing environment and its access/trust model. This alone would not approve public signing or funding; budget approval and the remaining technical/review gates are separate requirements.

`v8-fixture-generator.ts` implements only fixed deterministic fixtures derived with the pinned initializerless Schnorr account class (`SchnorrInitializerlessAccountContractArtifact`, matching `EmbeddedWallet.createSchnorrInitializerlessAccount`) and viem. It has no random seed input or entropy source. `generateActualAccounts` always throws. Fixture output directories must be new; directory/file modes are 0700/0600, files use exclusive no-follow creation, and writes are synchronized. The generator refuses node/RPC URL environment variables and historical credential paths. It does not open a socket or inspect a wallet store. The returned report contains only a fixture warning and public-metadata digest. All fixture addresses are test identifiers: NEVER FUND THEM.

`v8-account-generator.ts` implements the real isolated generator (`initV8RehearsalAccounts`), invoked via `npm run testnet:v8-upgrade-rehearsal -- --init-accounts --state-dir /var/lib/ans-signer/testnet-v8-upgrade-rehearsal-YYYYMMDD` exclusively as the dedicated `ans-signer` Linux user (mode `0700` `/var/lib/ans-signer`, inaccessible to unprivileged `grokbot` / TXE processes). It generates three independent Aztec 6 `SchnorrInitializerlessAccount` actors (`A`, `B`, `C`) and one independent Sepolia L1 funding EOA (`F`), writes secrets exclusively to `credentials.json` (`0600`, no hyphen in filename, `O_EXCL | O_NOFOLLOW`, fsynced), and outputs only `public.json` plus a SHA256 digest.

Never fund deterministic test fixtures or reuse historical accounts.
