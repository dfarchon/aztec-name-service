# Changelog

## Unreleased — V7 / SDK 0.7 compatibility

`runTx` and the registration flow now encode the call (arguments and function selector) before marking a transaction as possibly broadcast. A failure in that local step, such as the hashing WASM failing to load, never reached the wallet, so it is now a plain retryable error and leaves no `broadcastUnknown` marker; before, it was reported as `unknown_tx_state` and the plan waited for a manual hash check. Fee payloads are still built only inside `send`, so a fee method that asks the wallet for an authorization is not prompted twice.

The website's Content Security Policy now allows `data:` in `connect-src`. bb.js ships its WASM as an inlined `data:application/gzip` URL and loads it with `fetch()`; the previous `connect-src 'self' https: wss:` blocked that, so the first function-selector hash failed with "Failed to fetch". Every browser transaction therefore failed before the wallet saw it, and the SDK reported it as an unknown broadcast ("Transaction status is unknown"). Scripts, frames and workers still refuse `data:`. Verified on 2026-11-13 with Nulo 1.2.0 (Chrome Web Store build) on testnet-v6 against the live site with this exact policy: connect, capability grant, commit `0x2ee6905cd5b1a084e335e931eece6b90b0b5e36366f9f8756c049db45e4db3ad` and free registration `0x2b843baf03b6f533d21a0097e2b4f34ab242d67e709661f846f9c7cce07ac1da` of `nuloe2e2k1yu.fog`, sponsored network fees.

The public test deployment (testnet-v6) is now free. On 2026-11-11 a new Registry `0x2d4dcccfab0afa50d15d4ec3fd7c3ef4beac112a0379bb51102ffd8a18969bd7`, Resolver `0x0f737886154ada69533177a70a65da2194f1bf2771d4bc07eb05e11536eee12f` and NameRegistrarLaunch `0x210cd05dde1ae6e37894c5a4f632acf85a09a49f1445bc0190d18cc26a952f34` were deployed under new administrator keys: no payment token, one-year leases, a public minimum of 5 characters, the shared reserved list, not paused, no renewal horizon. It replaces the previous paid tiered deployment; names registered there are not migrated, and the site, monitor and docs now point only at the new Registry. The deployment, reserved-list and bootstrap transactions are listed below; every readback check passed. The previous paid manifest is archived as `deployments/legacy/testnet-v6-tiered.json`; the paid V6 acceptance runner (`test:testnet:v6`, which mints mAZTEC and pays) and the no-FPC rehearsal now load it and refuse the free manifest, so there is no public acceptance runner for the free deployment yet.

Names display with the `.fog` suffix (Fully Obfuscated Glyph): `alice.fog`, `team.alice.fog`. The suffix is presentation only, so contracts, hashes, records and existing names are unchanged. The SDK exports `NAME_SUFFIX` and `formatName(label)`; strip user input with `normalizeName(input, { suffix: NAME_SUFFIX })` and keep passing canonical labels to every other call. `normalizeName` still treats `.fog` as a parent label unless the option is given. The website shows `.fog` everywhere, accepts input with or without it, adds a drifting fog background (static under reduced motion), and shows “Free to mint” only when the live Registrar has no payment token.

Aztec 6 wallets (for example Nulo) refuse account and contract calls until the app holds matching capabilities. `requestFogCapabilities(reader, wallet, { app, sponsoredFpc })` checks the wallet network, then asks once for account reads, payment authorizations and the deployment's named contracts (Registry, active Registrar and Resolver, payment token, sponsor), with no wildcard contract, address book or private events. Pass its returned wallet to `connectFog`; it requests any later contract (a name's own Resolver, a new Registrar) before registering it, and ends the session with `wallet_rejected` if account permissions narrow. `scopeFogWallet`, `fogCapabilityManifest`, `fogSessionContracts` and `grantsFogContract` are exported for custom flows. Fee authorizations are requested as a CallIntent for the exact `transfer_in_private` call instead of a raw hash, so wallets that reject opaque hashes can show and sign the payment; the SDK verifies the intent hashes to the bound authorization and returns `unsupported` otherwise. The SDK sets no transaction salt and pins no protocol-contract address.

The SDK 0.7 release introduces a breaking `untrusted_resolver` branch in `AddressResolution`. Consumers must update exhaustive status switches before upgrading; use a minor version change while the SDK is pre-1.0. `resolvePrimary` can return stale with the same reason. `setPrimary` refuses unverified resolvers by default; `acceptUnverifiedResolver: true` is an explicit risk override, without bypassing network, lifetime or forward-record checks. Raw `RegistryReader.getAddress` does not validate trust.

V7 `AddressChangedV3.revision` carries the generation's record revision; V3–V6 carry the shared name revision. Indexers must select by protocol version. V7 holder revisions remain separate. Quote creation and commit require 300 chain seconds of remaining validity, including 180 seconds of proving/inclusion/checkpoint slack; this is a safety margin, not a latency guarantee.
